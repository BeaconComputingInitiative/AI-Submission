## 1. Computational principle

A440n⁶ uses a single consistent mathematical foundation while learning context-specific relationships from qualified observations. Musical scales, arpeggios, and chords provide an analogy for *structure*, not a claim that musical pitch is itself a universal mathematical algorithm.

The design separates three simultaneous interpretations of each eligible data group:

- **Scale — foundational/calculated line:** Eight deterministic algorithms applied under explicit preconditions.
- **Arpeggio — learned/operational line:** Four trainable algorithms that infer relationships from data; outputs remain hypotheses or forecasts.
- **Chord — reasoned line:** Reconciliation of observed/calculated constraints and learned hypotheses into a reasoned, evidence-referenced finding. This is an integration process, **not a thirteenth algorithm**.

**Computational definition: 8 deterministic + 4 learned → 1 evidence-aware Chord.**

The existing 8→4→2→1 *neural representation-composition* hierarchy is a separate mechanism and is not redefined as twelve algorithms.

## 2. Eight deterministic algorithms (Scale: K01–K08)

| ID | Algorithm | Input → outcome |
|---|---|---|
| K01 | Schema and value validation | Typed observations, units, ranges → accept/reject with reasons |
| K02 | Exact arithmetic | Valid operands and declared precision → verified arithmetic |
| K03 | Sequence and temporal ordering | Timestamps, event IDs, ordering rules → ordered evidence |
| K04 | Finite differences | Ordered numerical samples → first/higher differences |
| K05 | Ratio and proportion | Eligible numerator/denominator → ratios and rate changes |
| K06 | Descriptive and robust statistics | Numeric series → counts, mean, median, dispersion and robust summaries |
| K07 | Constraint and invariant verification | Explicit rules plus records → pass/fail/unknown with counterexamples |
| K08 | Evidence integrity verification | Source IDs, hashes, provenance, permissions → integrity assessment |

These algorithms provide *deterministic calculations*, not infallible claims about the physical world. Invalid or manipulated inputs, unsupported units, undefined divisions, ambiguous timing, missing provenance, and violated preconditions must not be silently interpreted as guaranteed truth.

## 3. Four learned algorithms (Arpeggio: L09–L12)

| ID | Algorithm | Learned responsibility |
|---|---|---|
| L09 | Pattern recognition | Identify recurring structures, regimes, trends and cycles |
| L10 | Contextual clustering | Group semantically or operationally related observations and detect variation |
| L11 | Predictive modeling | Predict future outcomes with uncertainty and calibration |
| L12 | Algorithm and rule induction | Propose and test candidate procedures, conditions and generating rules |

Training may use a shared encoder with separate evaluation heads, or separately trained modules; both options remain experimental. Agreement between heads sharing data is **not** independent corroboration. Predictions must retain model version, training provenance, confidence/calibration metadata and evidence references.

## 4. Chord: factual reconciliation

The Chord compares applicable deterministic outputs, independent observed evidence and learned candidate explanations *without averaging away disagreement*.

Output must distinguish:
- **verified_calculation:** The result follows mathematically from specified valid inputs.
- **supported_observation:** A source-linked finding backed by suitable records.
- **learned_hypothesis:** A potentially useful inference that is not independently verified.
- **contradicted:** A claim inconsistent with a verified constraint or evidence.
- **unresolved:** Insufficient evidence, inapplicable algorithms or conflicting hypotheses.

A finding is marked verified **if and only if** its relevant source, assumptions, derivation, validity and authorization checks pass. Training output cannot self-certify its own correctness. Novel business relationships must be evaluated on independent outcomes.

## 5. The Octet contract

The Condenser and Octet Tokenizer prepare groups of **up to eight eligible contextual Measures**, respecting the existing M1 bracket semantics. The Octet is neither necessarily eight words nor eight byte-sized tokens.

An Octet carries:
- ordered source-linked Measures, type/unit metadata and timestamps;
- full-resolution values, validation results, quality and missing-data masks;
- deterministic feature outputs (K01–K08);
- versioned learned representations (L09–L12), when available;
- exceptions, contradictions, confidence and uncompressed evidence links.

Partial Octets and insufficient history must be explicitly flagged rather than padded with fabricated observations. Derived 32nd-note or other rhythmic subdivisions are optional resolution encodings; they do not create new independent source facts.

## 6. Four-system deployment architecture

1. **Signatures:** Nine authorized observation interfaces; controls and provenance.
2. **Condenser:** Evidence ledger, Measures, Octets, Octet Tokenizer and pre-layout.
3. **A440n⁶:** Scale + Arpeggio + Chord, with later conversational generation.
4. **Conductor:** Isolated candidate training, held-out evaluation, policy-based promotion, and governed actions.

The shared foundation remains stable while each business-specific Tonal Variant develops isolated, authorized and versioned operational knowledge.

## 7. Execution and training behavior

Ingestion may continue while other Octets are refined and reasoned over. This pipeline is a proposed concurrency property, **not a demonstrated speedup**. A current active model must not be overwritten by in-flight training. Candidate weights are promoted if and only if integrity, validation, regression, tenant-isolation and policy gates all pass. The Conductor maintains rollback capability.

## 8. Acceptance tests (future work)

- Deterministic property tests: units, exact arithmetic, boundary values, invalid inputs, mathematical invariants.
- Octet tests: ordering, partial groups, provenance, exception preservation and data-leakage checks.
- Learned head tests: holdout prediction, shifted business contexts, calibration, algorithm induction and novel input ranges.
- Chord tests: supported vs hypothetical conclusions, contradictions, missing information and self-certification rejection.
- Operational tests: multi-tenant isolation, concurrent scheduling, checkpoint integrity and non-regressing model promotion.
- Benchmark alternatives: simple symbolic/statistical baselines and comparable neural architectures, with CPU, latency and memory measures.

Passing tests is required before claiming algorithmic comprehension, business readiness, continuous learning or natural-language competence.

## 9. Implementation maturity

M1: simulated evidence ledger/Measure/Octet pipeline demonstrated.
M2: numerical PyTorch prototypes and harmonic benchmarks performed.
M3: local simulated Conductor evaluation and candidate promotion reported; not yet established as a remotely published source milestone.
M4 chromatic 12-algorithm kernel: **architectural proposal only**. The twelve algorithms and Chord are not yet a trained, integrated product.
