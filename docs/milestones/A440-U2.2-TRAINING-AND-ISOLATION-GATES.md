# BEACON COMPUTING INITIATIVE
# A440 U2.2 — Isolated Adaptive Weight and Training Gates (Design Plan)
**Developer Seal:** CJB-DEV-2026
**Date:** 2026-11-03
**Status:** DESIGN / NOT IMPLEMENTED

## Why
A440 U2.1 learns numerically but updates a shared 128→12 backbone and shared role heads. The 2026-11-03 audit showed a second tenant's predictions changed by +0.13919793 when only the first tenant was trained. The same audit showed 60 feature-hash buckets with multiple labels. In a seven-industry synthetic forecast benchmark, the model beat persistence in only two businesses, and six-industry pretraining did not improve the unseen seventh industry's forecasts.

## Proposed development sequence
1. **Freeze a versioned common foundation.** Private customer data must not train shared weights without separately approved cross-tenant learning and governance. Company-specific training updates only that tenant's adapter.
2. **Use explicit feature identity and vocabulary contracts.** Study sparse categorical embeddings, deterministic namespaces, and collision-free identifiers instead of silently aliasing incompatible metrics.
3. **Train residual forecasters against robust baselines.** Compare persistence, trend, seasonality and A440 correction heads. Default to a statistical baseline when neural corrections are unsupported.
4. **Add CSV and JSONL loaders with identical validation.** Schema mapping must define tenant, entity, metric, numeric value, unit, event timestamp, availability timestamp, source, and provenance. Reject ambiguous dates/units and duplicates; fail closed for missing required fields.
5. **Enforce chronology.** No feature can use values observed or published after the forecast issuance cutoff. Partition training, candidate selection, and final evaluation by event time and publication availability.
6. **Govern candidates.** Retain approved weights and hashes. Accept if and only if evidence validation, tenant isolation, multi-window accuracy, per-metric regression, baseline comparison and rollback verification succeed.
7. **Confirm with new cohorts.** Prior seven-industry 2027 holdouts are already exposed during architecture development. Use newly generated/collected locked cohorts, multiple seeds, and confidence intervals for subsequent performance claims.

## Proposed acceptance tests
- Tenant A training leaves tenant B's approved state and forecasts bit-identical.
- Training one metric does not mutate unrelated tenant adapters.
- Shared foundation checksum remains unchanged during tenant-specific updates.
- CSV and JSONL equivalent observations yield equivalent evidence records.
- Invalid schemas, missing source identifiers, future leakage and nonfinite values cannot update production weights.
- Signed or otherwise authenticated source provenance is distinct from a mere SHA-256 content digest.
- Save/reload/rollback preserve exact model/adapter version and outputs.
- A440's residual arbiter improves on predefined baselines on untouched evaluation data, with appropriate error bounds.
- Existing 50 U2.1 tests, 12 weight tests and seven industry workflow invariants remain regression controls.

**No customer onboarding, daily scheduler, new neural training run or U2.2 release is implied by this document.**
